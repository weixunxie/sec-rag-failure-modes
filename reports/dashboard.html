Key Findings

WinnerTask-Aware retrieval scores 62.5% fully correct — 12.5 pts above Vanilla and 22.5 pts above Metadata-Filtered — by allocating retrieval budget based on question type (split-k for comparisons, filtered for single-entity).
SurpriseMetadata-Filtered is the worst overall (40%) despite having the lowest retrieval error rate (2.5%). Over-filtering collapses context for cross-entity questions, driving generation errors up to 57.5% — the highest of any strategy.
Top errorCitation Fabrication dominates across all strategies (47 / 120 answers, 39%). The model invents chunk IDs not present in the retrieved context — a generation-stage failure independent of retrieval quality.
ImplicationGeneration errors (40–57%) consistently outweigh retrieval errors in every strategy. Further retrieval tuning yields diminishing returns; prompt engineering and structured output validation are the higher-leverage next steps.

Error Stage Distribution (out of 40 per strategy)

Task-Aware eliminates retrieval errors entirely. Vanilla's 10% retrieval error rate (4 WRONG_ENTITY cases) comes from unfiltered similarity fetching wrong-company chunks. Metadata-Filtered's 57.5% generation error rate is the highest: over-filtering leaves too little context for the model to synthesize complete answers.

Answer Correctness by Task Type (0–2 scale)

Cross-company questions expose the sharpest gap: Task-Aware (1.7) vs Metadata-Filtered (1.0) — 70% higher. The single-ticker filter silently excludes the second company's evidence. All three strategies converge near the top on risk_factor (≥1.9), where section-aware chunking provides clean, focused evidence paragraphs.

Error Type Breakdown by Strategy

Task-Aware leads with 25 correct answers. Citation Fabrication is the dominant failure in every strategy (13–18 cases each) — the model invents chunk IDs not in the context. WRONG_ENTITY (4 cases, only in Vanilla) disappears completely once any metadata filter is applied.

Multi-Dimensional Score Profile

Task-Aware (green) leads on all five axes. The biggest advantage over competitors is on % Correct (scaled) and Faithfulness — both generation-stage metrics — confirming that better context coverage from split-budget retrieval directly reduces model fabrication, not just retrieval failure.

Correct vs. Error Counts per Strategy

Task-Aware: 25 correct, 15 generation errors, 0 retrieval errors — the cleanest profile. Metadata-Filtered: only 16 correct with 23 generation errors, the worst outcome despite having near-perfect retrieval precision. Confirms that context breadth matters more than retrieval purity on a diverse question set.

Retrieval Strategies
Vanilla50% correct›

Pure cosine similarity over all 2,954 chunks with no metadata filters. Treats every chunk equally regardless of company or year.

Strengths
  • No query parsing needed
  • Handles ambiguous multi-entity questions gracefully
  • Works across all question types
Weaknesses
  • 10% retrieval error rate — fetches chunks from the wrong company
  • Performance degrades as collection grows larger
Metadata Filtered40% correct›

Pre-filters the Qdrant collection by ticker and/or year before similarity search. Restricts the search space to the target company-year.

Strengths
  • Near-zero retrieval errors (2.5%)
  • High precision for single-entity questions
  • Faster search on large collections
Weaknesses
  • Collapses on cross-company queries — filter excludes the second company entirely
  • Highest generation error rate (57.5%) due to over-narrow context
Task-Aware62.5% correct›

Routes queries based on question type. Single-entity questions use metadata filtering; cross-year and cross-company questions split the top-k budget equally between both targets.

Strengths
  • Best overall accuracy (62.5%)
  • Zero retrieval errors
  • 70% higher correctness on cross-company tasks vs Metadata-Filtered
Weaknesses
  • Requires question metadata (task_type, companies, years) at query time
  • Slightly more routing logic to maintain
